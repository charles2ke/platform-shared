Why this package exists

Four applications needed the same identity, profile, and messaging behavior. Copying that logic per app produced divergent token claims, permission names, and retry semantics. platform-shared keeps those contracts in one place while staying framework-light: core modules have no HTTP or provider assumptions, and every store, scheduler, and channel is constructor-injected so each app can plug in its own persistence and providers.

Framework-light

Guards work on a request shape, not on Express/Fastify/Next internals. Adapters are opt-in.

Dependency-free

Only Node built-ins, so there is no transitive supply-chain surface to audit or patch.

Swappable everything

Account, profile, revocation, scheduler, dead-letter, and channel interfaces all ship with in-memory reference implementations.

Auth: tokens, sessions, and RBAC

Token lifecycle

  • issueTokenPair() access + refresh with a shared session id (sid)
  • refreshAccessToken() verifies a refresh token and issues a new access token only, with no rotation or replay detection
  • rotateTokenPair() issues a new access/refresh pair and detects replay of an already-rotated refresh token, revoking the affected session (and optionally the subject)
  • verifyToken(), decodeToken(), describeToken()

Revocation

  • revokeToken() single token
  • revokeSession() one login (access + refresh)
  • revokeSubject() log out everywhere
  • prune() drops expired entries

Authorization

  • createRoleRegistry() roles → permissions with inheritance
  • resolvePrincipal() exposes effectiveRoles
  • createAccessPolicy() action-keyed requirements
  • authorize() outside HTTP routes

Issue, guard, rotate, revoke

import {
  createAuthGuard,
  createRoleRegistry,
  InMemoryTokenRevocationStore,
  issueTokenPair,
  revokeSession,
  rotateTokenPair
} from '@charles2ke/platform-shared/auth';

const revocationStore = new InMemoryTokenRevocationStore();
const roleRegistry = createRoleRegistry({
  member: ['profile:read'],
  moderator: { permissions: ['post:delete'], inherits: ['member'] }
});

const tokens = issueTokenPair({
  subject: 'user-123',
  roles: ['member'],
  secret: process.env.PLATFORM_JWT_SECRET,
  issuer: 'platform-shared',
  audience: 'social'
});

const guard = createAuthGuard({
  secret: process.env.PLATFORM_JWT_SECRET,
  issuer: 'platform-shared',
  audience: 'social',
  revocationStore,
  roleRegistry
});

const principal = guard(request, { permissions: ['profile:read'] });

// Refresh endpoint: rotate, revoke the presented token, and treat replay as compromise.
const rotated = rotateTokenPair(tokens.refreshToken, {
  secret: process.env.PLATFORM_JWT_SECRET,
  issuer: 'platform-shared',
  audience: 'social',
  revocationStore,
  onReuseDetected: ({ subject }) => securityLog.warn('refresh replay', { subject })
});

// Logout.
revokeSession(principal.claims, { revocationStore });

Policies that also apply to jobs and consumers

import { createAccessPolicy } from '@charles2ke/platform-shared/auth';

const policy = createAccessPolicy({
  'profile.get': { permissions: ['profile:read'] },
  'profile.update': { permissions: ['profile:write'] },
  'profile.delete': { roles: ['admin'] }
}, { roleRegistry });

const profiles = new ProfileService({ store, policy });
await profiles.update(id, { timezone: 'Africa/Nairobi' }, { principal });

Profiles: one canonical model

A single profile shape — id, displayName, contact, preferences, timezone, locale, avatarUrl, status, metadata — with normalization for display names, emails, locale/timezone defaults, and status values. 

import { InMemoryProfileStore, ProfileService } from '@charles2ke/platform-shared/profile';

const profiles = new ProfileService({
  store: new InMemoryProfileStore(),
  defaults: { locale: 'en-US', timezone: 'UTC' }
});

const profile = await profiles.create({
  displayName: 'Charles',
  contact: { email: 'charles@example.com' },
  preferences: { units: 'metric' }
});

Swap InMemoryProfileStore for an app-owned adapter by extending ProfileStore; unimplemented methods throw structured errors instead of failing silently.

Notifications: send, schedule, retry, replay

Delivery

One API for email, SMS, and push. {{variable}} template rendering and delivery statuses of sent, failed, partial, or pending.

Scheduling

schedule(), listScheduled(), cancelScheduled(), and dispatchScheduled() for cron or worker drains, with pluggable queue adapters.

Resilience

Exponential backoff (retryDelayMs * factor ** (attempts - 1), capped), per-channel retry of partial failures, dead-letter capture, and replayDeadLetters().

import {
  CHANNELS,
  InMemoryDeadLetterQueue,
  InMemoryNotificationScheduler,
  MockChannelAdapter,
  NotificationService
} from '@charles2ke/platform-shared/notifications';

const notifications = new NotificationService({
  adapters: {
    [CHANNELS.EMAIL]: new MockChannelAdapter({ channel: CHANNELS.EMAIL }),
    [CHANNELS.PUSH]: new MockChannelAdapter({ channel: CHANNELS.PUSH })
  },
  scheduler: new InMemoryNotificationScheduler(),
  deadLetterStore: new InMemoryDeadLetterQueue(),
  maxScheduleAttempts: 4,
  retryDelayMs: 30_000,
  retryBackoffFactor: 2,
  maxRetryDelayMs: 15 * 60_000
});

await notifications.send({
  channels: [CHANNELS.EMAIL, CHANNELS.PUSH],
  to: { email: 'user@example.com', userId: 'user-123' },
  subject: 'Welcome {{name}}',
  body: 'Hi {{name}}, your account is ready.',
  variables: { name: 'Charles' }
});

await notifications.schedule(reminder, new Date(Date.now() + 60_000));

const { processed, retried, deadLettered, pending, pendingKnown } =
  await notifications.dispatchScheduled();

Shared: config, errors, logging

  • loadConfig() reads environment values, applies defaults, and coerces numeric fields, without validating them.
  • requireJwtSecret() separately validates that PLATFORM_JWT_SECRET meets the minimum length.
  • PlatformError carries a stable code, HTTP status, message, and details.
  • Logger hooks accept any object exposing debug, info, warn, and error.

Enterprise hardening

Supply chain

  • No runtime dependencies
  • Dependabot for npm and GitHub Actions
  • npm audit gate in CI
  • npm provenance on publish

Code security

  • CodeQL security-extended on push, PR, and weekly
  • Least-privilege workflow permissions
  • Credentials never persisted in checkouts
  • Private vulnerability reporting in SECURITY.md

Runtime safety

  • Constant-time JWT signature comparison
  • Explicit issuer, audience, and expiry checks
  • Synchronous revocation so guards cannot be bypassed
  • Structured errors that do not leak internals

Delivery quality

  • CI matrix on Node 22 and 24
  • Executable examples covered by tests
  • Issue, PR, and ownership templates
  • Semantic versioning with migration notes

Operators must still set a 32+ character PLATFORM_JWT_SECRET, back revocation with a shared store across instances, keep access-token TTLs short, terminate TLS in front of guarded services, and monitor dead-letter records.

Adoption path for a consuming app

  • Install or vendor the package, then load env values with loadConfig().
  • Wrap createAuthGuard() in the app router, or mount the Express/fetch adapter.
  • Replace in-memory stores with app-owned persistence by extending the shipped interfaces.
  • Standardize role and permission names across apps before enabling policies in production.
  • Keep domain logic in the app; keep identity, profile, and notification contracts here.
